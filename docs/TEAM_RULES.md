
## Git ブランチ戦略

本プロジェクトでは、以下のような Git フローに従って開発を進めます。

### ✅ 運用ルール

- `main`: 本番環境にデプロイされるコード（保護ブランチ）
- `develop`: 開発の統合ブランチ（常に最新の安定状態を保つ）
- `feature/*`: 機能ごとに作成。作業が完了したら `develop` に PR
- `fix/*`: バグ修正ブランチ
- `chore/*`: Lint 設定・CI/CD 設定などの修正用
- `docs/*`: README やチームルールなどドキュメント編集用

```
main
└─ develop
   ├─ feature/xxx    ... 機能実装用
   ├─ fix/xxx        ... バグ修正用
   ├─ chore/xxx      ... 依存更新・設定ファイル変更など
   └─ docs/xxx       ... ドキュメント編集用
```

### 🔁 Pull Request ルール

- `develop ← feature/*` の形で PR を作成
- レビュワー 1 名以上必須
- マージ後、不要になったブランチは削除する
